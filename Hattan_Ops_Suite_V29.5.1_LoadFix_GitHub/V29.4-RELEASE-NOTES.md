# Hattan Ops Suite V29.4 — Full Current CleanBase Bridge

Source snapshot uses the current `vwork(3).dbf` (DBF header dated 2026-09-18) together with the current customer, phone and ticket-detail tables supplied for migration.

Included in this build:
- 27,533 CleanBase customer master records.
- 158,540 non-deleted master tickets from the current `vWork` snapshot.
- Ticket garment/service descriptions joined from `vWorkTckt` where a current master-work key matches.
- Customer first/last activity dates, ticket counts and historical ticket totals derived from current `vWork`.
- Full customer directory filters for recent activity and joined date.
- Lazy ticket-history loading so the POS does not place 158k legacy tickets in browser memory at startup.
- Existing V29 customer names/phones are preserved when they can be matched by legacy/customer number.

Important source limitation: CleanBase stores some customer name/street fields in an encoded form in `vCust.dbf`. V29.4 does not guess or fabricate decoded names/streets. Those records remain searchable by customer number/available phone until a verified mapping/decoder is available. Sensitive legacy card credentials are not embedded in the browser build.
