# Hattan Ops Suite V29.6–V29.7

## V29.6 — Customer directory
- Customer List loads the full CleanBase directory (`legacy-v296/customer-directory.json`: 27,574 customers; names, addresses and phones for the 4,126 on the 09/01/23–09/28/26 Customer List). It is read-only and never saved to the browser or synced, which fixes the stuck "Loading customer directory…" and the ~300-customer list.
- A CleanBase customer is added to the live customer list only when opened (from Customers or Drop Off search).
- Drop Off search also finds CleanBase customers.
- Balances: completed CleanBase tickets count as settled; each customer's CleanBase account balance (vCust CU98Y, as of 9/18/26) is a "balance forward" line; CleanBase credits become store credit.
- Replaces `v29.4-full-cleanbase.js`, `v29.5-customer-master.js`, `v29.5.2-customer-data.js`, `v29.5.3-customer-load-fix.js` in `index.html` (files kept for rollback).

## V29.7 — Batch charge cards on file
- Payments screen: charge every unpaid card-on-file ticket for **Today** or **All unpaid up to today**, with per-ticket untick, 30-day-old warning and a declined list. Manager only.
- Uses the existing `clover-charge` function (server re-checks ticket + 3% fee, per-ticket idempotency, refuses already-paid/charged tickets).

## Clover settings (Netlify environment variables)
`CLOVER_ENVIRONMENT`, `CLOVER_MERCHANT_ID`, `CLOVER_PUBLIC_TOKEN`, `CLOVER_PRIVATE_TOKEN` (secret). Values are needed in both Production and Deploy Previews contexts. Settings take effect on the next deploy.

## V29.8 — Card on file
- Customer profile shows a "Card on file" box (Add / Replace). New Customer has an "Add a card on file" checkbox that opens the Clover secure form after saving.
- No email needed: when the customer has none, Clover gets `hattancleaners141+c<customer#>@gmail.com` (kept off the profile, never used for receipts).

## V29.9 — Card price + 3% cash discount (replaces the 3% card fee)
- The catalog stays the **cash** price list. Tickets written from V29.9 on are priced at the **card price** = cash ÷ 0.97 per line (flag `pricing: 'card-price-v299'`, `cashPrice` stored).
- Card payments (counter, pickup, batch, Clover server check) pay the shown price with no fee. Cash/check payments get a "Cash discount (3%)" so they pay exactly the cash price.
- Printed tickets: card total, plus "Cash / check price" while unpaid, or "Cash Discount 3%" once paid in cash.
- Tickets written before V29.9 keep the old rule (3% added on card) until paid.

## V29.10 — Drop Off "Pay Now · Card" charges Clover
- Before: Pay Now → Card only marked tickets paid in the POS; no card was charged.
- Now (Clover connected): tickets are created unpaid, synced, then charged through `clover-charge`. A result window shows **Charge successful** (Print Ticket / Close) or **Charge unsuccessful** with the reason (Try Again / Leave Unpaid — Pay at Pickup / Print Ticket).
- Charges wait for the store sync to finish so the server always sees the new ticket (also applied to the Payments batch).
- Store credit applied at drop-off now reduces the card charge on the server too.
- Fixed: the "Tickets created" message showed the old 3% fee on top of the card price.
